Section 1: Authentication
--------------------------------------------------

Test Scenario: Valid user login
Input: POST /api/auth/login with valid body { "email": "user@test.com", "password": "SecurePassword1!" }
Expected Output: 200 OK, returns user object, and sets a JWT token in an HTTP-only cookie.
Actual Output: 200 OK, user object returned, cookie header present.
Result: Pass

Section 6: Edge Cases
--------------------------------------------------
Test Case ID: TC-EDGE-001
Test Scenario: User tries to leave the queue after they've already been marked as "served"
Input: PUT /api/tickets/leave/:ticketId by the customer AFTER the provider executed /api/tickets/serve/:queueId.
Expected Output: 400 Bad Request. The system business logic should reject cancelling a ticket that has resolved naturally.
Actual Output: 400 Bad Request indicating the ticket cannot be aborted in its current state.
Result: Pass

Test Case ID: TC-EDGE-002
Test Scenario: Multiple concurrent walk-in additions
Input: Firing 10 concurrent POST requests to /api/tickets/walk-in simultaneously.
Expected Output: Database handles concurrency successfully. 10 unique, incrementing queue numbers are assigned accurately without overlaps.
Actual Output: 10 x 201 Created responses parsed successfully, sequence is pristine.
Result: Pass

Test Case ID: TC-EDGE-003
Test Scenario: Provide malformed/empty body attributes
Input: POST /api/organizations passing empty strings for strictly required validations.
Expected Output: 400 Bad Request. Validation layer halts DB operation and responds before Mongoose schema strictness failure.
Actual Output: 400 Error providing an array/string specifying the missing components.
Result: Pass
